# FlowBridge macOS — экспериментальная версия 0.2.0

Основа: Windows-релиз 0.1.4, commit `812908666a52e723d382c53a34797838ff27e300`.
Windows-файлы и подписанный Firefox XPI не меняются. Это предварительная версия для добровольных тестировщиков, не проверенный публичный релиз.

## Что подготовлено

- Нативное приложение `FlowBridge-Setup.app`, собираемое для Apple Silicon и Intel (Universal 2), macOS 13+.
- В выборе отображаются приложения, обнаруженные Launch Services по идентификаторам поддерживаемых браузеров. Обнаружение Comet на реальном Mac ещё требуется подтвердить.
- Установщик копирует свои файлы в пользовательский Application Support, открывает выбранный браузер и показывает необходимые шаги подтверждения.
- Chromium и Safari используют экспериментальное расширение 0.2.0. После подтверждения установки оно открывает подготовку Flow; если доступ к сайту ещё не разрешён, потребуется нажать кнопку разрешения.
- Firefox получает неизменённый Mozilla-signed XPI 0.1.1. После установки нужно нажать значок FlowBridge → «Открыть Flow».

Установка в Chrome, Edge, Comet, Opera и Яндекс требует режима разработчика и выбора распакованного расширения. Это пока не равно автоматизации Windows-установщика. Приложение не выдаёт сообщение «Установлено» по одному факту копирования файлов.

## Проверка Safari

Для первого теста подойдёт Safari 18.4+ с временной установкой расширений. В Safari откройте Настройки → Дополнения → функции для веб-разработчиков. В появившемся разделе Developer разрешите неподписанные расширения, выберите Add Temporary Extension и укажите папку `safari` из тестового комплекта. Разрешите FlowBridge доступ к `flow.google.com`.

Временная установка прекращается после выхода из Safari или через 24 часа. Разрешение неподписанных расширений также сбрасывается при выходе. Для постоянного распространения нужен отдельный подписанный Apple-пакет; подпись Mozilla для Safari не подходит.

Приложение показывает путь к подготовленной папке кнопкой «Скопировать путь». В системном выборе папки используйте ⌘⇧G. Самостоятельно отключать Gatekeeper, SIP или проверку подписей системы не нужно. Тестовая `.app` имеет только ad-hoc подпись; macOS может заблокировать её запуск. При блокировке используйте отдельные пакеты расширений для ручного теста и сообщите об ошибке.

Для варианта с Xcode есть `build-safari.sh`: официальный packager создаёт Safari-контейнер, затем Xcode собирает его без подписи издателя. Контейнер получает ad-hoc подпись для локального запуска и добавляется в установщик; при выборе Safari установщик копирует его в пользовательскую папку Applications. Полученная `.app` также требует разрешения неподписанных расширений. Возможность такого запуска должна быть проверена на машине тестировщика. Отдельный ZIP папки Safari остаётся запасным вариантом временной загрузки.

Safari использует cookies, доступные его API, без Chromium-фильтра `partitionKey`. Доступность всех разделённых cookies не подтверждена. Общие cookies `.google.com` не изменяются.

Упаковщик Xcode предупреждает о ключах `world` и `persistent`. В данных совместимости MDN ключ `content_scripts.world` указан для Safari 18+, но такое предупреждение нельзя считать доказательством работы. Обязательный ручной тест должен подтвердить выполнение engine.js до кода Flow в основном мире страницы. Автоматическая проверка WebKit запускает сам адаптер через нативный document_start user script и не заменяет этот тест Safari-расширения.

- https://webkit.org/blog/16574/webkit-features-in-safari-18-4/

## Сборка и проверки

На Linux можно выполнить:

```sh
node tools/build.cjs
node macos/build-extension.cjs
node --test
bash -n macos/build-app.sh
bash -n macos/build-safari.sh
```

На Mac с Xcode:

```sh
bash macos/build-app.sh
bash macos/build-safari.sh
```

GitHub Actions выполняет сборку на macOS и сохраняет ZIP в артефактах. Сборка Xcode, проверка ad-hoc подписи и JavaScript-тесты не подтверждают работу Google Flow в настоящем Safari. WebKit/JS-модель не заменяет Safari с его разрешениями.

## Что должен проверить человек на Mac

1. Записать версию macOS, браузера, тип процессора и наличие VPN. Не присылать cookies, токены или пароль.
2. Закрыть браузер, запустить установку. Проверить список браузеров, загрузку расширения и открытие Flow.
3. Повторить при открытом браузере без Flow, затем со старой вкладкой Flow и посторонним сайтом. Сохранить работу в Flow перед тестом: его старые вкладки закроются при подготовке.
4. Проверить сохранение постороннего сайта, окна и размера, запрос доступа только к Flow, вход в аккаунт и отсутствие сообщения о недоступной стране.
5. В Safari отдельно проверить выдачу/отказ разрешения для Flow, перезапуск Safari, временную установку и включение Xcode-контейнера.
6. Записать экран при ошибке. Платную генерацию автоматически не запускать.

Пока эти пункты не пройдены, совместимость с живым Flow и Safari остаётся неподтверждённой. Никакие настройки браузера, политики организации, системные защиты или профили аккаунтов установщик напрямую не переписывает.
